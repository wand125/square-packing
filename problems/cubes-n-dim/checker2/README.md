# m2check2

An independent, std-only Rust interval checker for the claim in `SPEC.md`:

\[
F(R)=\sum_{e=0}^3 |R_{e0}|\left(2-\sum_{j=0}^3|R_{ej}|\right)<1,
\qquad R\in SO(4),\quad \max_e R_{e0}^2\le 2/3.
\]

It was implemented from `SPEC.md` alone, without reading or reusing the first system (`../checker`) or its
design notes. The near region max_e R_e0² ≥ 2/3 is delegated to the hand lemma (`../PROOF.md` §3).
The full run is complete: see **Full run** at the end of this file and `receipt.json`.

## Coordinates and two necessary specification corrections

Identify a vector with the quaternion `x0 + x1 i + x2 j + x3 k`.
Hamilton multiplication follows from `i² = j² = k² = ijk = -1`, or

\[
(a_0,a_v)(b_0,b_v)=(a_0b_0-a_v\cdot b_v,
 a_0b_v+b_0a_v+a_v\times b_v).
\]

Consequently left multiplication by `p` and right multiplication by `conj(q)`
have matrices

```text
L(p) = [ p0 -p1 -p2 -p3 ]   T(conj(q)) = [ q0  q1  q2  q3 ]
       [ p1  p0 -p3  p2 ]                [-q1  q0 -q3  q2 ]
       [ p2  p3  p0 -p1 ]                [-q2  q3  q0 -q1 ]
       [ p3 -p2  p1  p0 ]                [-q3 -q2  q1  q0 ]
```

The implementation constructs each column as `p * e_j * conj(q)` directly
from the multiplication table. Thus its numerator is precisely `B = L(p)T(conj(q))`,
with bilinear entries. For example,

```text
B00 = p0 q0 + p1 q1 + p2 q2 + p3 q3
B01 = p0 q1 - p1 q0 - p2 q3 + p3 q2
B10 = p1 q0 - p0 q1 + p3 q2 - p2 q3.
```

Write `N = (sum p_i²)(sum q_i²)`. Multiplicativity of quaternion norm gives
`BᵀB = N I`, so **R = B / sqrt(N)**. The specification's literal denominator
`|p|² |q|²` would give `RᵀR = I/N`, not a rotation. We use `sqrt(N)`; equivalently,
the squared entries have denominator `N`. On unit quaternions the determinant
is +1: it is continuously either +1 or -1 on the connected domain `S³ × S³`
and is +1 at `(1,1)`.

Each quaternion is represented projectively by one of four faces: a coordinate
of largest magnitude is divided out, making that coordinate +1 and the other
three coordinates lie in `[-1,1]`. There are 16 face pairs and six free coordinates.
However, **four positive faces represent S³ only up to sign**. Choosing positive
faces independently for `p` and `q` can change `R` to `-R`; the double-cover identity
`R(p,q)=R(-p,-q)` does not remove this extra sign. The tests exhibit this even
for rotations already satisfying C1–C3.

To keep the required 16 face pairs without losing coverage, each box represents
both its entry enclosure `E` and `-E` for the purposes of symmetry constraints.
It is discarded only if C1–C3 exclude **both** branches. All remaining bounds
are identical for the two branches because they use absolute values. Since
`-R` is in SO(4), and `F(-R)=F(R)`, this restores complete coverage. Checking
only the positive-face matrix against C1–C3 would not be justified.

For completeness, the quaternion map is onto SO(4). Given `A`, let the unit
quaternion `u=A(1)`. Then `L(conj(u)) A` fixes 1 and restricts to an SO(3)
rotation on the imaginary quaternions. An axis-angle rotation there is
conjugation by `a=cos(theta/2)+axis*sin(theta/2)`, as follows by multiplying
quaternions. Therefore `A(x)=(u a) x conj(a)`. Numerical tests additionally
recover `p,q` from independently generated SO(4) matrices, rather than only
sampling rotations generated by the quaternion formula.

## Symmetry argument

Row sign flips make column 1 nonnegative. A row permutation sorts its entries
in descending order (C1). A permutation of columns 2–4 sorts the absolute values
in row 0 (C3). Sign flips of columns 2 and 3 make their row-0 entries nonnegative
(C2). If the resulting determinant is -1, flipping column 4 fixes it and changes
none of C1–C3. This constructs signed permutation matrices `P_L,P_R`, with
`P_R` fixing column 1, that give a representative in SO(4).

Absolute row sums and the corresponding absolute first-column factors are
unchanged by these column operations and merely permuted by row operations.
Thus `F` and `max_e u_e²` are invariant. This proves it suffices to check the
constrained representatives. Sorting ties and zero entries cause no exception.
The randomized reduction test performs these operations, checks all constraints,
checks determinant +1, and checks preservation of F.

## Interval proof and closing rules

`I` implements finite binary64 closed intervals. Addition, subtraction,
multiplication, reciprocal and square root round each computed endpoint outward
by `next_down`/`next_up`. Squaring handles intervals crossing zero explicitly;
absolute value and negation are exact endpoint operations. No fast-math or
external numerical libraries are used. The arithmetic assumes IEEE-754
round-to-nearest binary64 and correctly rounded basic operations/square root.
Inputs and intermediate quantities here are bounded, with quaternion norms at
least 1; an invalid interval or nonfinite value triggers failure rather than
silently accepting a box.

`D` carries a value interval and six interval derivatives. The ordinary product
and chain rules propagate derivatives through quaternion multiplication and
`N^(-1/2)`. For each matrix entry, evaluate both the naive interval and

\[
R_{ij}(c)+\sum_{k=0}^5 [\partial_k R_{ij}](B)(B_k-c_k).
\]

The point evaluation at `c` is itself outward-rounded interval arithmetic. The
mean-value expression encloses the entry on the entire box because the derivative
intervals hold along every segment from `c` to a point of the box. Intersect the
naive interval, this first-order enclosure, and `[-1,1]`. This is not a bare
natural interval evaluation. `F` is then bounded using those tightened entries:

\[
[F]=\sum_e |[R_{e0}]|\,
 \left(\left(2-\sum_j |[R_{ej}]|\right)\cap[0,2]\right).
\]

Intersecting the row slack with `[0,2]` is valid because a unit row in dimension
four has l1 norm at most 2. No auxiliary objective bounds are used.

A leaf closes only by:

1. **Discard:** C1, C2 or C3 is definitely violated, using strict endpoint
   comparisons, separately for each of `E` and `-E`; both must be excluded.
   Examples are `hi(u_i)<lo(u_(i+1))`, `hi(u_i)<0`, and
   `hi(abs(R02))<lo(abs(R03))`. Equality never suffices for discarding.
2. **Near:** a downward-rounded lower bound on `|u_e|²` is at least an
   *upward-rounded* enclosure of the exact rational `2/3`. Comparing against
   an ordinary nearest-rounded `2.0/3.0` would be unsafe.
3. **F:** the outward-rounded upper endpoint of `[F]` is strictly less than 1.

Otherwise split the longest coordinate interval, breaking ties cyclically with
depth. Task endpoints and the tested midpoint splits are exact dyadics; the two
children share their midpoint and their union is the parent. Split selection
and timing are heuristics/control decisions, never proof predicates. A stalled
midpoint is a FAIL. At the depth limit an unresolved box is a FAIL, not a closed
leaf. The first four failures per task include their six intervals, depth and
reason in the journal.

## Tasks, resource limits, logging and resume

Each face pair is cut into `4^6 = 4096` boxes of side 1/2. There are 65,536 tasks.
For task ID `t`, `face=t/4096`, `p_face=face/4`, and `q_face=face%4`.
The six base-4 digits of `t%4096` (least significant first) select coordinate
intervals `[-1+d/2, -1+(d+1)/2]`. Free p coordinates in ascending coordinate order
come first, then free q coordinates. The closed boxes cover all faces, including
their boundaries. Maximum depth is measured from each task root.

Threads claim tasks through an atomic counter. A mutex serializes completed-task
JSONL writes; each line is immediately flushed before its task is registered
as finished. There is no cross-process journal locking: use only **one process
per log file**. Flushing is not an `fsync` durability guarantee.

A default **8-second wall-time budget per task** bounds scheduling latency.
After it expires, every pending subtree root is counted as a failed leaf, with
reason `time_limit`; these are never reported as closed or silently omitted.
In the version used for the full run, `--task-seconds` accepted `(0,9]`; the published source accepts
`(0,3600]` (see **Full run**). Small caps keep tasks short on a normally scheduled machine,
but OS suspension cannot be bounded.
A larger proof depth cannot evade this resource cap. Time-limit failures can
need smaller initial tasks or a faster enclosure in future versions.

For each task, and again for all journal tasks combined, the checker verifies

```text
boxes = 2 * (discarded + near + closed + fails) - tasks.
```

This follows because every internal node has exactly two children, including
when unfinished subtrees become failed leaves. The human-readable identity
precedes the final JSON summary. Its `ok` is true **only** when all 65,536 tasks
are present, no failures exist, and the identity holds. Totals include prior
journal records, even outside the currently selected range. `new_tasks` counts
the tasks executed in this invocation; `skipped` counts selected existing tasks.
`seconds` sums per-task elapsed times, whereas `wall_seconds` is this invocation's
wall time including startup and journal loading.

Resume validates the journal version, grid, depth limit, task IDs, duplicate IDs,
counters, tree identities and failure sample shape. An interrupted/malformed
last line, or a missing final newline, is rejected: inspect and remove only the
incomplete final record before resuming. Finished tasks, including failed tasks,
are skipped. To retry failed tasks use a fresh journal; old failures do not
become successes merely by resuming. A different `--max-depth` requires a fresh
journal. Thread count and time budget may change, since neither can turn a
failed/unfinished box into a proof. Journals are trusted local checkpoints, not
cryptographically authenticated certificates for accepting third-party claims.

## Build and run

Rust 1.86+ is required for stable `f64::next_up/next_down`; no crates are used.
Tests here used Rust 1.99.0 on aarch64 macOS.

```sh
cargo build --release --jobs 2
cargo test --jobs 2 -- --test-threads=2
target/release/m2check2 --selftest

# Small trial; --last is EXCLUSIVE. Repeat the command to resume.
target/release/m2check2 --jobs 2 --first 32764 --last 32772 --log my-trial.jsonl

# Exercise depth failure on a separate journal.
target/release/m2check2 --jobs 2 --first 0 --last 2 --max-depth 0 --log my-fails.jsonl
```

Options: `--jobs N` (default 1), `--first ID` (default 0), `--last ID`
(default 65536, exclusive), `--max-depth N` (default 60, range 0–120),
`--task-seconds S` (default 8), `--log FILE` (default `m2check2.jsonl`),
`--selftest`, `--help`. Without range options a checking invocation selects the
full task set (about 24 minutes with two workers on a laptop, see **Full run**).

Exit codes: 0 for a complete successful check, successful selftest, or help;
2 for an incomplete check or any failed leaves; 1 for option, journal or worker
errors. A partial zero-failure run intentionally returns 2 and `ok:false`.
Selftest is separate from proof checking: it exits 0 on success and emits
`selftest_passed:true`, but reports `tasks:0, ok:false` to avoid claiming a proof.
Assertions/panics are errors, never successful certificates.

## Tests and pre-run measurements

See `tests.log` for commands, outputs, exit codes, resumptions and explicit
failure records. Eight unit tests cover interval edge cases, all task IDs,
closing predicates, depth/time failure accounting, malformed/duplicate/configuration
journal rejection, and idempotent resume. The randomized geometry test is also
available as `--selftest`, with a fixed reproducible seed:

- 500 independent SO(4) matrices generated by Gram–Schmidt and determinant fix;
  quaternion recovery, orthogonality, determinant +1, and simultaneous sign
  invariance. Recovery projects onto the 16 orthogonal quaternion coefficient
  matrices to obtain the rank-one matrix `p qᵀ`.
- Reduction into C1–C3 and F invariance; conversion of the reduced result to
  positive faces reproduces it up to sign. 145 samples required the negative sign.
- 1,024 random boxes across all 16 face pairs, including broad boxes;
  10,240 interior/end-corner samples check entry inclusion, F upper enclosure,
  point orthogonality/determinant, and certified near classifications.

Random tests are implementation checks, not a replacement for interval rigor.

## Full run

Run on a laptop (aarch64 macOS, Rust 1.99.0) with `--jobs 2`, default depth 60 and default 8-second cap:

```sh
target/release/m2check2 --jobs 2 --log full.jsonl
```

- All 65,536 tasks ran (23 min 48 s). 102 tasks reached the 8-second cap; their unfinished subtree roots were
  recorded as `time_limit` failures (1,150 in total). No box failed for any other reason and the depth limit was
  never reached.
- Those 102 tasks (`retry_ids.txt`) were then run again, one task per invocation (`--jobs 1`, two invocations
  at a time) and one fresh journal each, with `--task-seconds 3600`:
  `m2check2 --jobs 1 --first ID --last ID+1 --task-seconds 3600 --log retry/ID.jsonl`. All closed with 0 failures; the longest took 117 s.
- The published `src/main.rs` is the retry source with one comment line removed (a note in a unit test); no
  code changed. The full-run source differs from the retry source only in the bound accepted for
  `--task-seconds` (`9.0` and the message text `(0,9]`). The rule for closing or discarding a box is identical in
  all versions. All three SHA-256 values are in `receipt.json`.
- Accepted records: the 65,434 tasks with no failure in the full run, plus the 102 retried tasks. Together they
  cover every task exactly once with 0 failures: 192,488,546 boxes, maximum depth 30, and
  boxes = 2 × leaves − tasks. `../verify_logs.py` checks this from the logs in the release asset.
